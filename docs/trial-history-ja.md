# 試行錯誤の記録

目的はCursorの監督判断を活用しながら、同じ作業・品質でCursor総トークンを減らすこと。段階目標はStep 1＝10%以下、Step 2＝2%以下、Step 3＝1%以下です。費用削減率、文字数削減率、Strata側のトークン削減率とは区別します。

## 1. 共有キューと逐次監督（v0.2）

可変数の依頼元・深度選択・共有キューの自動テストは41件成功しました。ただし機能テストの成功はトークン削減を意味しません。

実Cursor評価は予定12試行のうち10試行、5対応ペアを完了。Cursor単独395,574に対し旧Strata方式834,455で、約2.11倍でした。残りは方針変更で中止・未実行です。[実測の詳細](token-evaluation-ja.md)と[機械可読データ](token-evaluation-results.json)を参照。

学び：作業をローカルへ委譲しても、Cursorがツール操作・結果取得を繰り返すと削減できない。

## 2. 短い判断だけをCursorへ渡す方式（v0.3）

背景・目的・現状・要求を送り、Cursorが短いJSON指令を返す方式へ変更。実装・待機・テスト・別コンテキストでのレビュー・適用はローカルで処理しました。

試行順と結果：

1. decision-eval：要約が800文字を超えて停止。Cursor呼出しなし。
2. decision-eval2：Cursorがplan ID欄に説明文を返し拒否。14,077トークン。IDの完全コピーを指示。
3. decision-eval3：ローカル圧縮要求が失敗。Cursor呼出しなし。
4. decision-eval4：レビューJSON後の根拠文で解析停止。13,558トークン。差分未適用。
5. decision-eval5：編集・最終テスト・独立レビュー・適用成功。13,436トークン。適用後の4テストも成功。

成功した1組はCursor単独66,680に対して20.15%、79.85%削減でした。Step 1には未達です。開発中のCursor失敗試行も含む合計は41,071で、この合計に79.85%という率を適用してはいけません。[検証詳細](decision-verification-ja.md)。この状態を`2ebd81a`に保存しました。

## 3. 指令短縮・段階的コード取得（未コミットの追加実装）

共通情報の重複排除、ticket＋依頼番号による短い返答、受け入れ条件の明示、Python ASTによる必要シンボルだけの取得を追加しました。同じ判断本文は1,022文字から939文字へ短縮しました。

しかし実機では以下の3試行とも未適用です。終了コード0でもmissionがblockedなら失敗と判定します。

- decision-compact-eval：16,104トークン。JSONコードブロック後の根拠文で解析停止。
- decision-compact-eval2：13,558トークン。未認識のVerification notes欄で停止。
- decision-compact-eval3：13,426トークン。レビューJSONが状態表示の1,500文字制限で切断され、解析停止。

旧形式だけを同時期に再測定した診断は13,863トークンで、Cursorはinspectを選択しました。実装・適用まで実行した比較ではありません。3試行＋診断で56,951トークンを使用しました。これらを成功した削減率として扱いません。

自動テスト71件はローカル13.650秒、gdx-spark11.712秒で成功。ただし実LLMとの統合失敗を捉えていませんでした。拡張のモック検証と、IDE実操作の検証も区別します。

## 4. 原因と次の実験への反映

- 文字数を減らしても、Cursorの固定コンテキストと生成量が支配的で総トークンの改善は確認できない。
- 監督がrunを返すだけでは、高性能モデルの設計判断を十分に活用できない。
- 表示用要約を機械判定に流用してはいけない。回答全文を証拠として保存し、判定時だけ参照する。
- テスト成功と受け入れ条件の充足は同一ではない。独立レビューと統合後テストを維持する。
- 次は関連する複数ファイルの一つの作業を対象に、事前調査→Cursorの方針判断→Strataの自律実行を比較する。Cursor単独側にも同じ全作業を一括で渡す。

## 記録と再現性

[試行別使用量](trial-history-results.json)には成功・失敗・診断を分けて保存しました。生ログはローカル情報を含むため公開せず、失敗原因と実測内訳を公開します。[前段階の再現手順](decision-mode-ja.md#同じ課題で再評価する)と固定pagination課題を保存しています。モデル出力は非決定的で、全く同じトークン値の再現は保証しません。

[次の方針委譲実験](policy-experiment-ja.md)では、仮説・事前固定条件・手法・全試行結果・限界を別に記録します。

## 5. 方針委譲の3試行

[方針委譲実験](policy-experiment-ja.md)を実施しました。Cursor単独は各15テスト成功。新方式は3回ともStrata事前調査で停止し、監督判断・実装へ到達しませんでした。削減率は算出不可です。比較対照を含む今回のCursor消費265,595トークンも記録し、次はStrata単体の安定性を先に確認する方針としました。
