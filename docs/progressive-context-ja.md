# Step 1に向けた情報取得・指令形式の改善

## 目的と変更

Cursorの監督判断を維持し、入力と出力の双方を減らすための追加実装です。79.85%削減を記録した`2ebd81a`を比較元として残しています。この変更だけでStep 1を達成したとは扱いません。

- 共通の背景・目的・現状・深度をバッチ内で一度だけ送信。受け入れ条件は省略せず、明示的に追加。
- Cursor出力をticketと`[依頼番号, 方針, 深度または質問]`に短縮。詳細ID・revisionの復元はプログラムが行う。
- ticketはrepo、契約全文、資料、revisionを含めて計算。古い資料・別バッチ・依頼の欠落／重複・深度の矛盾を拒否。判断パケット全体は24,000文字を超えたら切らずに停止。
- CLIと拡張のコピー機能が同じプロンプト生成処理を使用。
- Strata用にPython ASTの`code_context`を追加。関数／クラス一覧から必要な本文だけを取得し、SHA-256で古い内容を検出。ページングで続きも取得可能。CRLFも元のバイトと一致するハッシュを使用。
- レビューは根拠をJSON内部へ返すよう指定。既存モデルのJSONコードブロックと認識済みの根拠欄も保存できるように修正。不明な追記や追加判定JSONは拒否。

[Serena公式のツール・段階的情報開示](https://oraios.github.io/serena/01-about/035_tools.html)を設計上の参考にしました。ソースコードの流用やSerena MCPへの接続は行っていません。今回のAST機能はPythonのみで、言語サーバーの参照解決や多言語対応はありません。呼出元・import・モジュール直下の処理は既存search/read_fileで確認します。Cursorの入力にツール定義や取得本文を追加しません。

## 検証目的と手法

短縮で判断条件を落とさないこと、指令の取り違えを防ぐこと、部分読取りで古いコードを混ぜないことを自動テストします。実機では前回と同じpagination課題・同じ初期コード・同じ4テストを使い、Cursor判断→Strata編集→独立レビュー→適用の全経路を確認します。

文字数はトークン数の代用にはしません。同じ1依頼の本文は1,022文字から939文字へ短縮しましたが、総量はCursorが報告する入力＋出力＋キャッシュ読込＋書込で集計します。推論出力も含むため、表示JSONが短くても出力トークンが必ず減るわけではありません。

## 解釈と今後

Cursor内部の固定コンテキストとモデル判断の変動が大きく、今回の本文短縮だけではStep 1の達成根拠になりません。Serena型の部分読取りはStrata側の調査効率・扱えるコード量を改善する仕組みであり、それ自体のCursorトークン削減効果は未測定です。

次は実務に近い複数依頼を事前に固定し、Cursor単独でも同じ依頼をまとめて処理する条件と比較する必要があります。複数差分の統合・適用・統合後テストまでを測り、比較の分母だけ増やして合格にはしません。現状、複数依頼の差分自動統合は未実装です。

## 後続実験での修正

状態表示用の1,500文字の要約をレビューJSONとして解析していた問題は、[方針委譲実験](policy-experiment-ja.md)の前提修正として、回答全文の証拠保存とresponse_idによる取得へ変更しました。概要と正式な判定データを分け、全文のハッシュ・打切り状態・取得上限を検証します。過去の失敗試行を、この修正後に成功したことには書き換えません。
