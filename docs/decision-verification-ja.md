# v0.3判断方式の検証（2026-10-09）

## 結果

新方式で、短い資料→CursorのJSON指令→Strata実装→最終テスト→別コンテキストのStrataレビュー→適用まで実機で成功しました。Cursorの呼出しは1回で、Workerの待機・コード修正・証拠取得・適用確認には使っていません。

同じ初期コードと4件のテストを使用した1組の比較：

- Cursor単独：**66,680トークン**。入力10,399、出力937、キャッシュ読込55,344、書込0。テスト4件成功。
- 新方式：**13,436トークン**。入力8,637、出力499、キャッシュ読込4,300、書込0。適用後に独立実行したテスト4件成功。
- 比率：**20.15%（約1/4.96）**。削減率：**79.85%**。
- **Step 1の10%以下は未達**。Step 2の2%、Step 3の1%も未達。

新方式の入力（キャッシュを含む）は12,937トークンで、短い資料にしてもCursor内部の固定コンテキストが残ります。出力499トークンには、表示JSONだけでなくモデルが報告する生成量が含まれます。CLIに厳密な総トークン上限を強制できる仕組みは確認できていません。

## 手法

Cursor CLI 2026.10.01-e373342、モデルcomposer-2.5、各条件の新規セッションを使用しました。課題はpages(items,size)の末尾欠落と不正sizeの修正。初期subject.pyとtest_subject.pyのSHA-256一致を確認しました。変更範囲はsubject.pyだけです。

単独条件は通常のCursor Agentに調査・修正・テストを依頼。新方式はソースを置かないworkspaceで、4項目の資料と計画IDだけを送信し、ツール使用を禁止して短い指令を取得しました。実装と独立レビューはgdx-sparkの実Strataを共有コーディネーター経由で実行しました。autoでCursorがmediumを選択しました。正確なパッチハッシュと利用者の事前適用許可を確認して適用しています。

指令の予算は本来不足するため、機能と固定負担を測るこの試験に限り`--measure-over-budget`を明示しました。予算判定はfalseのままで、合格にはしていません。

総量はCLIのresult.usageの入力・出力・キャッシュ読込・書込の合計です。Strataトークンを混ぜず、料金とは区別します。使用量定義は[Cursor公式](https://cursor.com/docs/sdk/typescript)を参照してください。

## 開発中の失敗試験も記録

完成経路の比較とは別に、次の不具合を実機で確認・修正しました。

1. 計画用の長い要約が800文字を超え、停止。短い依頼は利用者原文と実測状態から直接資料を作る方式に変更。長い依頼だけローカルで一度圧縮。
2. Cursorがplan欄へIDではなく説明文を返し、検証で拒否。この試行のCursor使用量は14,077。IDをそのままコピーする指示を明記。
3. ローカル圧縮要求が失敗し、Cursorを呼ばず停止。未知の結果を自動再実行しない。
4. レビューのJSON後の根拠文を不正JSONとして停止。この試行のCursor使用量は13,558。認識した根拠欄を監査記録へ保存する処理を追加。不明な追記は拒否。

上記の失敗試行で測定されたCursor使用量も含めると **41,071トークン**です。単独1回に対して約61.60%で、こちらもStep 1未達です。失敗した試行をなかったことにしてプロジェクト全体の削減を主張しません。

## 再現方法

[decision方式のCLI手順](decision-mode-ja.md#cliでバッチ判断とトークンを計測)を使用します。同じ課題のCursor単独使用量を測り、その値をbaseline-tokensへ設定します。Step 1は`--step 1`、Step 2は`--step 2`、Step 3は`--step 3`です。

1. 同じ初期ソース・同じテストから、単独用と新方式用の別Git repoを作る。
2. 単独用はCursor CLIの新規セッションで修正させ、stream-jsonのresult.usageを保存。
3. 新方式はmissions.jsonを用意し、prepare→cursor→execute→statusを実行。allow_apply=trueは専用のお試しrepoだけに設定。
4. 両方で同じ4テストを独立実行し、初期ファイルハッシュ、最終変更範囲、終了状態、全Cursor呼出しのusageを照合。
5. 段階の上限と品質を両方満たすか判定する。測定漏れや失敗を除外しない。

[機械可読結果](decision-evaluation-results.json)へ各トークン内訳・初期ハッシュ・Strata使用量を保存しています。生ログにはローカルパス等があるため公開していません。一時SSHとコーディネーターは終了後に停止しました。

## 限界と次のStep 1作業

単純なPython課題1組の機能確認で、統計的な削減率ではありません。IDE Chatでの操作と利用明細は未検証です。固定入力の償却には判断のバッチ化が必要ですが、同じ作業量・品質・統合まで含めた比較が必要です。複数差分の自動統合と大きい差分の分割レビューは未実装で、現状は停止して証拠を残します。

Step 1の次の課題は、実務に近い複数ファイルの作業と複数依頼を事前に定め、バッチ化の効果を同条件で測ることです。小課題の未達を隠すために分母だけ増やす比較はしません。
