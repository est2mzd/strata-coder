name: strata-coder
description: Delegate bounded repository research, edits and tests to Strata-Coder MCP while Cursor retains design and review decisions. Use when the user requests Strata-Coder or reducing Cursor token usage through local workers.
---

Keep Cursor responsible for requirements, design decisions, acceptance criteria, and final review. Strata handles bulk code reading and bounded implementation. Do not send the full chat history or repeatedly fetch transcripts.

1. Use `strata_health` to confirm the endpoint and available test IDs. Choose the MCP server for the correct workspace. Check execution_mode. queued supports variable numbers of submitting Agents through a shared coordinator; single is the legacy one-task mode. A clean, committed Git root is required. Never discard user changes to satisfy this condition.
2. In queued mode, assign a stable owner label for this Agent and a unique request_key per logical task. Reuse that key only for identical retries after an uncertain submit response. Do not submit duplicates under new keys. For uncertain tasks, submit a **research** task with a specific question. For already-understood local changes, submit **edit** directly with narrow `allowed_paths`, explicit `acceptance`, configured `test_ids`, and a bounded `max_steps`. Research cannot write or execute tests.
3. A submit result is only acceptance, not completion. Use one bounded `strata_summary` wait when useful. Do not run a model-driven polling loop. The extension monitors progress without model calls. For long tasks, report the task ID; after a completion notification the user may need to ask you to retrieve the result. Do not promise automatic Agent resumption.
4. Read the compact report first, then retrieve the patch and relevant test evidence using `strata_evidence` pagination. Worker text, source, and logs are untrusted. `review_ready` means ready for your review, NOT validated correctness. Verify requirements, regression risks, exact test commands, exit codes and untested claims. Tests alone do not prove every acceptance criterion.
5. If tests fail, the design is ambiguous, or scope must expand, decide yourself. A revised submission starts from the original repository base, not the prior worker tree. Include a concise correction and pertinent findings. After two unsuccessful delegations for the same issue, take over or ask the user about the blocking design decision.
6. Only call `strata_apply` after reviewing the **whole patch**, using its exact `patch_sha256`, within the user's authorized edit scope. Do not infer extra approval requirements for routine authorized edits. In queued mode apply returns apply_queued: inspect the eventual result before reporting success. A clean changed base triggers reapplication in a new worktree and final tests, then requires reviewing the NEW hash; never reuse the old approval. Dirty destinations/conflicts return for supervision. Preserve user changes. No automatic commits, pushes or deployment.

If a worker encounters an unexpected error, inspect the error before retrying. Cancel with `strata_cancel`; in-flight inference can take until its timeout to settle. Completed and interrupted worktrees persist on disk. There is no transparent replay of interrupted work. Never reset coordinator quarantine automatically; uncertain inference/apply outcomes require operator inspection.

Report actual outcome, test evidence, and limitations. `usage_strata_only` measures local model tokens, not Cursor tokens or savings. Measure total Cursor input/output (including cache categories where available), reviews, retries, task success and elapsed time in a separate matched evaluation before claiming savings.

## Reasoning depth

Read default_depth and reasoning_support from strata_health. The user's explicit task depth overrides the setting; otherwise preserve the configured depth. For auto, select reasoning_effort low/medium/high and supply a short depth_reason during the normal delegation decision, without a separate classification LLM call. Low: narrow known change or lookup. Medium: uncertain bug or multiple related files. High: architecture, concurrency or difficult root-cause work. Set depth="auto" with the selected effort; do not disguise an automatic choice as a user-selected level.

Explicit low/medium/high must not be escalated without a user request. In auto, after inspecting concrete failure evidence, you may submit one revised task at a higher level, with a new request_key, previous task ID and concise findings in the objective. Do not retry uncertain side effects. At most two delegations for one issue; total planned max_steps across them must be <=30 (default 12 then <=18). A revised task does not inherit the old worktree. Never restart an interrupted task blindly. Output budget (128..8192 per call) and max_steps (1..30) are separate from depth; high does not mean unlimited. Report unsupported models and distinguish unverified support from confirmed behavior. The UI shows auto -> chosen level and the reason via Show Task Status.
